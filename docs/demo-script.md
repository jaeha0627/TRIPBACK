# Tripback Pleos 데모 시나리오

## 데모 목적
Tripback v5의 '가는 길 → 체류 → 오는 길' 사용자 흐름을 시연하고, 차량 데이터·AI·내비게이션 연동의 진위를 명확히 구분한다.

## 대표 시나리오
1. **계획:** 가족 여행, 08:30 출발, 18:30 귀가, 안전여유 30분 입력.
2. **AI 응답:** 구조화 조건을 Spring Boot에 전송하고 검증된 코스 2안(여유형/알찬형)을 표시.
3. **선택:** 방문지·식당·카페 및 필수 방문지를 확인하고 코스 선택.
4. **내비:** '내비게이션 안내 시작' → NaviHelper 첫 목적지 전달 (실연동 여부를 영상에 표기).
5. **도착·체류:** 차량 이벤트가 가능하면 실제 콜백, 불가능하면 '모의 도착' 버튼으로 시연.
6. **지연:** 체류가 25분 길어짐 → 예정 귀가 시각과 안전여유 감소.
7. **재구성:** 서버가 선택 방문지 축소·제외를 *제안* → 운전자는 안전한 상황에서 승인.
8. **귀환:** 변경 일정을 차량 내비에 반영하고 완료/기록 화면 확인.

## 녹화 시 표시할 항목
- Android 앱과 Pleos 에뮬레이터 버전
- 실제 AI 응답 vs mock JSON
- 실제 SDK 내비 요청 vs 화면상의 모의 경로
- 실제/가상 차량 상태, ETA, 장소 정보
- 서버 API 호출 및 오류 처리가 실제 동작했는지 여부
- 릴리스 APK 설치·실행 화면(실제로 검증된 경우)

## 예비 시나리오
- 인터넷 연결이 끊겼을 때 마지막 검증 일정 유지
- 주어진 귀가 마감이 불가능한 일정 경고
- 사용자 지정 필수 방문지를 AI가 임의 삭제하지 않음

> 영상 초반에 '어떤 부분이 실데이터이고 어떤 부분이 시뮬레이션인지'를 설명해야 한다.
